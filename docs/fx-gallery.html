GreyNOC // GreyIQ

Three renderings for the terminal

Each one is a full-screen set piece for the moments gn has something to show — a hunt resolving, a mark locking, a scope coming into view. These are drawn in the browser from the same arithmetic the CLI runs, at the same 78×24 character grid, so what plays here is what the terminal draws. Pick one and it goes in the hero.

python scripts/fx_gallery.py all

wopr

The threat board

WarGames, 1983

Arcs launch from the node to every in-scope asset, impact with an expanding ring, and leave a marker blinking in its severity colour. The trail drains away so the board stays readable. DEFCON falls as each proof lands.

  • arc one asset, one verification pass
  • DEFCON worst confirmed severity so far
  • teletype the engine's own progress lines
cryptlock

The decryption cascade

Sneakers, 1992

Glyph rain with white-hot heads. The wordmark emerges inside it as scrambling characters that lock cell by cell, each flashing white on the way to solid, while the real handshake seals in the log underneath. The rain thins out so the last frame is just the mark.

  • log ML-KEM-768, X25519MLKEM768, ML-DSA-65
  • lock left to right, jittered, never a wipe
  • loops with no narrative — made for a splash
wireframe

The rotating scope

Hackers, 1995

A wireframe globe turning under a fixed tilt, the far hemisphere dropped to near-black so it reads as line art. Blips surface as they rotate into view; the reticle closes on each in turn and runs a leader line out to the readout panel.

  • blip an asset, placed by its own coordinates
  • panel scope, primitives, surface mapped
  • lock one asset at a time, in severity order
The terminal is the source of truth: scripts/fx_gallery.py. Every scene there is a pure function of time — draw(canvas, t), no frame-to-frame state — which is why the same arithmetic drives this page off requestAnimationFrame without a rewrite.
